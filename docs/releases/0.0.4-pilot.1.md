# Legura 0.0.4 Pilot 1 Candidate

This is release preparation, not a published download or a stable production
release. Publish only after full release CI and promotion from dev to main.

## Included

- Administrator category management: validated creation/editing, literal search,
  pagination and slug-confirmed non-destructive deletion.
- Admin/Editor category assignment for saved posts, with transactional authority
  checks and independent, idempotent Add/Remove operations.
- Combined category/status/title filtering of the server-paginated Posts list.
- Public category catalog and archives containing only published, non-trashed
  posts, native pagination, appearance/locale support and links from stories.
- Empty, draft-only and missing category archives share a safe 404 response.

## Upgrade Contract

This candidate includes migrations through 020. Migration 020 creates category
tables and integrity triggers without rewriting existing posts or image bytes.
Rollback refuses to discard category data or assignments. Category slugs have no
redirect aliases: renaming changes the public URL and the old URL returns 404.

The backup reader accepts producer versions 0.0.1 through 0.0.4 explicitly.
Older readers reject backups written by 0.0.4. Reading an archive does not migrate
it or authorize service activation. Back up the database and referenced media,
verify the archive and rehearse on an inactive copy. Preserve the stopped source
installation and rotate session secrets for recovery activation. Never overwrite
the active database, media, configuration or running package.

## Release Gates

- Full registry CI, including category HTTP privacy/pagination/lifecycle checks
  and Aegis browser checks with page scripts enabled and disabled.
- Native Linux/Windows packaging, package integrity and toolchain-free startup.
- Historical 0.0.1/0.0.2 compatibility and pre-Pages upgrade rehearsals.
- A separate pinned 0.0.3-source package to 0.0.4 candidate rehearsal: exact
  migration prefix, verified backup/recovery, unchanged source hashes, preserved
  post authorship/image bytes, fresh login, category assignment/public visibility,
  Trash/unpublish behavior, restart persistence and category-aware backup recovery.

Tooling is pinned to published cargo-axonyx 0.8.10, runtime 0.8.4 and the existing
UI dependency. No new framework/UI release or production database migration is
part of this release preparation. There is no automatic update or rollback.
